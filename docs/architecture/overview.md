# Architecture and dependency decisions

`cmd/forge` owns Wails application lifetime, the native save dialog, CLI profile validation, and optional loopback server. Wails uses the installed OS WebView rather than shipping Chromium. The same HTTP handler serves the embedded offline Svelte bundle and typed JSON API. Assets and documentation are embedded at compile time; no CDN or remote font is used.

`internal/service` owns session models, bounded job history, stored user profiles, cancellation, and the end-to-end pipeline. Expensive work happens outside the frontend thread. Only one job runs at a time. Requests have byte limits and same-origin checks; the optional server binds loopback only. Profile files never carry executable paths. Engine selection is a separate explicit local user setting.

`internal/geometry` reads binary/ASCII STL and bounded ZIP/XML 3MF mesh resources/build instances. It normalizes units and applies affine transforms. It computes exact triangle area/bounds and signed-volume sums for consistently wound closed meshes; volume of defective meshes is not guaranteed. Rotations/scales are rebased before applying bed-centre/min-Z placement. Overhang surface and shortest triangle edge are documented heuristics; the native engine handles slicing, thin-wall paths and bridging.

`internal/config` validates embedded Draft 2020-12 schemas and semantic hardware/material constraints. No schema reference is fetched at runtime. Hardware limits cannot be overridden by preferences. Portable schema version 1.0 rejects unknown versions explicitly. Examples are embedded and marked as simulation fixtures.

The normal application starts with an empty printer catalogue. Simulation data is exposed only through an explicitly named development-fixture helper used by tests. Six generic material recipes and one explicitly unverified user-requested PLA Plus 115°C recipe are separate from machine capabilities. Validated imported printers and active selection persist on disk. `/api/materials` checks recipes against the selected machine and returns reasons when declared temperature, cooling or layer constraints cannot be met. Slicing requires a saved imported profile and rejects unsaved changes to its hardware values.

The first-run interface is printer setup. `/api/printer-template` supplies an unresolved null-valued draft, `/api/docs` reads only embedded Markdown under the documentation root, and `/api/profile-kit` assembles an offline ZIP of documentation, schemas and that draft. These endpoints never fetch documentation, schemas or assistant content from the network.

`internal/optimizer` evaluates deterministic bounded candidates using analytical volume/time/quality/strength proxies, caches repeated settings, constructs a Pareto frontier, and refines using coordinate search. Candidate time/material/quality/strength costs differ by objective. Estimates are not global optima or validated mechanical predictions. Orientation is user controlled or chosen by the frontend's bounded geometry heuristic; it is never silently changed after placement.

`internal/analysis` builds a mesh BVH and performs bounded deterministic area-weighted downward probes with cancellation. `/api/models/{id}/analyze` requires an imported printer and uses the same transform as the job. At most two analyses run simultaneously, and interactive requests time out after 30 seconds. Readiness includes support, bridge-like, bed-contact, slenderness and detail findings with documented assumptions. Risk triangle indices refer to the imported mesh order and are rendered in one buffered overlay.

Support recipes translate to explicit native contact gaps, XY separation, density, interfaces and sheath settings. Auto enables support only on a positive geometric recommendation; Optimized, Easy removal and Stable explicitly enable it. Auto/Optimized with automatic shape compare at most organic and snug while holding all other print settings fixed. Every candidate must pass G-code validation. Selection minimizes 0.75 times support-filament ratio plus 0.25 times print-time ratio, normalized to the first valid candidate; equal scores preserve deterministic order. Explicit shape choices skip comparison. Native bridge exclusion stays enabled. The complete job, including baseline, has a 15-minute cancellation deadline. These metrics establish neither removal force nor structural stability.

`internal/engine.Backend` isolates the native process. The PrusaSlicer adapter serializes validated machine/material/selected settings into a fresh INI and writes an inert transformed STL. Imported 3MF settings, engine profiles, postprocessing hooks and scripts never cross this boundary. Start/end snippets must be literal declared G/M-code; unsupported semantics fail static validation before export. Native crash, cancellation and timeout become actionable job errors.

`internal/gcode` tracks units, XYZ/extrusion modes, homing, temperatures/waits, extrusion/retraction debt, speeds, flow, coordinates, excluded-region segment intersections and shutdown. Unknown commands/work offsets/arcs are rejected. Positive deposited extrusion yields filament length and mass; engine time comments are preferred, with an acceleration-limited fallback. Static validation cannot prove physical safety. Preview uses the validated file and batched feature-colored geometry buffers.

Packaging is native per OS. Source uses Windows/macOS/Linux Wails abstractions; this workspace's recorded verification applies only to the platform actually tested. See development/testing.md. Engine-inclusive redistribution requires a licensing audit and corresponding source; out-of-process operation is not a licensing exemption.
