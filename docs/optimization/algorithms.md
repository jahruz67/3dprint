# Search, constraints and termination

The optimizer first validates printer, material and preferences, rejects nonfinite/degenerate geometry, checks build-volume dimensions, and constructs a feasible baseline. The backend separately checks exact transformed placement and excluded regions. Material/nozzle intersection bounds layer height; line width ranges from 1.0 to 1.35 nozzle diameters; wall/infill minima are user functional constraints.

The conservative throughput bound is `speed*lineWidth*layerHeight <= min(machineFlow,materialFlow)`. This uses rectangular bead area, slightly greater than the rounded bead area in the estimator, so the cap is conservative within the model. Selected speed, travel and acceleration never exceed machine limits. Temperatures are not search variables: they come from the verified material profile and must fit the machine.

Search begins with a fixed low-discrepancy Halton sequence in bases 2, 3, 5, 7 and 11, covering continuous layer/width/infill/speed variables and bounded wall counts. Three native infill patterns are cycled; their geometry is generated by the mature backend, while the analytical estimate does not claim a pattern-specific validated quality benefit. The seed stage visits at most 64 candidates. Coordinate pattern search then evaluates signed perturbations around the best candidate; stalled rounds halve the mesh. Search terminates after 18 rounds, small mesh convergence, cancellation or the configured unique-candidate budget (16–4096).

Each candidate setting tuple is cached in a map within the job. Duplicate candidates do not spend evaluation budget. Candidate memory is bounded by that budget. No unbounded Cartesian product is enumerated. Context cancellation is checked at entry, in each iteration and before returning. The baseline is always evaluated, so the chosen objective cannot regress relative to the same analytical baseline.

An incremental nondominance filter reports a Pareto frontier over time, mass, quality error (minimize) and strength proxy (maximize). Stable sorting by time and deterministic candidate order keep repeated runs identical. The scalar objective selects one point; the Pareto count indicates explored tradeoffs, not exhaustive knowledge of the feasible region. Worst-case Pareto filtering is quadratic in the budget, bounded to 4096 candidates. The default 256 budget is deliberately modest.

This is a deterministic bounded search, not an exact nonlinear solver and not a proof of global optimality. It meaningfully changes native slicing parameters according to calculated objective differences, while acknowledging geometry and physical calibration limits. Placed-mesh [support analysis](support-analysis.md) now recomputes unsupported/contact estimates, and a separate bounded native comparison can select organic or snug support by calculated support-filament/time. Automatic candidate-orientation search, adaptive layer scheduling, exact bridge validation and wall-thickness solvers remain future extensions.
