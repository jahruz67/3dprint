# G-code translation and export

The JSON printer format describes capabilities; it does not contain arbitrary engine CLI arguments or postprocessing commands. The application writes a private native-engine configuration and invokes PrusaSlicer as a child process with an argument array. It never constructs a shell command from profile content. Engine-process failure and cancellation are surfaced to the user, and partial output is not exportable.

The chosen candidate controls actual native layer height, extrusion width, perimeter count, infill fraction/pattern, print speed and support enablement. Machine and material profiles constrain nozzle/filament diameters, flow, temperatures, fan and retraction. Top/bottom shells remain enabled. The model transformation and placement are applied before slicing, then checked against usable volume and excluded regions.

Preview uses the generated G-code rather than drawing the input model in toolpath colors. The parser tracks XYZ position, absolute/relative XYZ and E modes, extrusion origins, feed rate, layer changes and native feature comments. Batched line segments distinguish travel, perimeter, infill, support and other extrusion. Displayed filament length and mass derive from positive deposited extrusion and filament cross-section/density; estimates do not measure discarded purge or printer calibration errors unless explicitly represented in the file.

Export requires generated-output validation against the same profile, including known command support, coordinate bounds, temperatures, extrusion-state consistency, motion limits and required startup/shutdown structure. The validator is static; it cannot establish bed adhesion, homing accuracy, actual wiring, firmware configuration, step loss, collision clearance beyond supplied regions or thermal safety. Never bypass a failed validation just to export a file.

The generated dialect is deliberately narrower than a firmware's entire command set. It accepts uppercase numeric words, decimal numbers, compact words such as `G1X20E0.4`, and semicolon comments. Parenthesized comments, line numbers, checksums, inch units, relative XYZ moves, G92 XYZ/work offsets, arcs, arbitrary macros and text-display payloads are rejected. Core validated command semantics are `G0/G1` linear movement, `G4` dwell, `G21` units, `G28` pre-deposition homing, `G90` absolute XYZ, `G92 E` extrusion-origin reset, `M82/M83` E mode, `M104/M109` nozzle target/wait, `M140/M190` bed target/wait, `M106/M107` fan, `M204` bounded acceleration, `M84/M18` motor release, `M400` synchronization, numeric `M73` progress and single-tool `T0`. Every command must also be declared supported by the selected printer. Listing a command in the profile cannot add parser semantics: for example `M201`, `M203`, `M205`, `M220` and `M221` are rejected at output validation even if the firmware supports them. The reference command list records firmware capabilities beyond the narrower export dialect.

Profile snippet validation checks literal structure and declared commands; it does not independently interpret every numeric parameter. Full output validation is authoritative before export. Export limits are 128 MiB of G-code, 64 KiB per line and 2,000,000 preview segments. Motion uses absolute XYZ and explicit E mode after G90; extrusion requires completed temperature waits. Unretraction is distinguished from fresh deposition so repeated retract/unretract cycles do not inflate filament statistics. Stationary positive deposition and mid-print homing are outside the supported dialect. These conservative restrictions may reject legitimate specialized firmware jobs; the application does not silently weaken them.

Analytical optimizer estimates are labeled as estimates, and actual sliced metrics are reported separately. Baseline analytical comparisons use the exact baseline stored in the report. An analytical difference must not be presented as a measured slicing or physical print improvement. Shorter text files do not imply faster prints.

Parameters are allowlisted per command: movement accepts only XYZEF; G28 only XYZ; G92 only E; heater commands only their documented S/R/T subset (single T0); fan PWM only S; acceleration only P/S/T; dwell only P/S; M73 numeric P/R/Q/S. Mode changes, synchronization, fan-off, T0 and motor release accept no extra parameters. Fourth-axis moves, nonzero tool selection, M84 timeout commands and other unknown words are rejected. Final heater targets must both be zero after deposition and a genuine final motor release must be present. Any movement or homing after motor release is rejected.
